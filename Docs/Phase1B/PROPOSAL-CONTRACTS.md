# Structured proposal contracts — version 1 design

19 October 2026 · Phase1B.2B implements the ten Domain values and pure Workspace serialization/hashing/validation described below. No broker or approval/effect authority was implemented. Real context observations and effects remain1B.2C/1B.4 gates; see [completion evidence](PHASE1B2B-COMPLETION.md).

## Typed value model

All values are immutable, Equatable where meaningful, and Sendable-compatible. Strings/bytes cross boundaries; Foundation process/URLSession/store/vendor objects and handles do not. Explicit top-level `schemaVersion: Int = 1` versions CodingProposal, WorkspaceSnapshot, ProposalValidationResult, ApprovalRequirement and VerifiedChangeResult; nested values use their enclosing version at the supported model-facing entry point. Standalone Codable value decoding is for trusted internal data, not a supported hostile-byte boundary. Unsupported versions reject before interpretation. A future migration must be explicit, never best-effort reinterpretation.

| Type | Fields / closed variants | Owner and meaning |
|---|---|---|
| ProposalIdentifier | canonical lower-case UUID string | WF assigns to a response envelope; identifier grants no permission |
| ProjectIdentifier | canonical lower-case UUID string | Trusted registry assigns; never a path or authority; unknown project rejects |
| CodingProposal | schemaVersion, proposalID, projectID, baseSnapshotDigest, changes:[ProposedFileChange] | Decoded hostile model data; WF wraps it with task/operation/session/generation/provider/artifact/deadline/context identity |
| WorkspaceSnapshot | schemaVersion, projectID, snapshotDigest, entries:[relativePath, fileRevision] | Trusted context service constructs from authorized observations; model's claimed digest is compared, never trusted |
| ProposedFileChange | exactly `create(relativePath, expectedRevision:absent, utf8Content)` or `update(relativePath, expectedRevision:sha256, utf8Content)` | Bounded full replacement text, not a script/patch executable. No delete, rename, chmod, binary, command, URL or environment case |
| ExpectedFileRevision | exactly `absent` or `sha256(lowercaseHex64)` | Creation requires confirmed absence; update requires matching current regular-file bytes |
| ProposalValidationResult | schemaVersion; exactly rejected(reasons) or validated(proposalDigest, projectID, baseSnapshotDigest, expectedPostSnapshotDigest, policyRevision) | WF-only derived data, not dispatch authority; invalid proposals yield no partially usable validated plan |
| ProposalRejectionReason | unsupportedSchema, unknownField, unknownOperation, malformed, oversized, invalidPath, duplicateTarget, projectMismatch, unknownProject, staleSnapshot, revisionMismatch, unauthorizedTarget, unsafeFileType, conflict, cancelled, deadlineExceeded, policyChanged | Closed safe error codes with bounded index/relative-path references, no raw source/secret echo |
| ApprovalRequirement | schemaVersion, proposalDigest, projectID, baseSnapshotDigest, policyRevision, operationDigests, taskID, operationID, sessionID, generation, deadline, maximumTTLMilliseconds | Trusted policy computes exact review scope. A requirement says approval is needed; it is NOT a grant or an approval decision |
| VerifiedChangeResult | schemaVersion, proposalDigest, projectID, baseSnapshotDigest, observedPostSnapshotDigest, receipts, verificationScope, evidenceDigest, outcome | WF verifier constructs after broker receipts and independent observation; never accepted from a model/provider response |

`receipts` contain relative target, intended before/after hashes and actual disposition `notApplied/applied/uncertain`, plus durable intent/outcome references. `verificationScope` is exactly `fileContent` or `containedBuildAndTests`; `outcome` is `verified/failed/partial/uncertain`. Verified file bytes do not imply a successful build. Missing command containment means containedBuildAndTests cannot be claimed. These data types are not proof their producer is trusted. Current public constructors create inert summaries only; future trusted observation/verification paths and private one-use effect capabilities must establish provenance, never arbitrary decoded report data.

## Strict wire boundary

The model-facing schema is CodingProposal only. Unknown keys anywhere (including command, shell, permissions, approval, verification), unknown operation/revision discriminators, duplicate JSON keys, invalid types, unsupported schema versions and trailing documents reject. No coercion/default version, ignored unknown cases, lossy UTF-8 repair or automatic decoding into an effect/approval/result envelope. Swift synthesized Codable alone does not reject unknown/duplicate keys; CodingProposalCodec uses a bounded raw-byte scanner to enforce these checks explicitly before typed construction.

Initial limits: complete input ≤1 MiB UTF-8, maximum nesting16, ≤20 changes, ≤256 KiB content/change with aggregate content plus envelope ≤1 MiB, ≤1,024 UTF-8 bytes/path, ≤32 path components, ≤128 bytes/identifier fields (UUID representation remains canonical36), ≤32 rejection diagnostics each ≤256 bytes. Empty change lists reject. Check declared/raw limits before allocating large objects; decoded string bytes and repeated/escaped keys also count. Stream assembly needs its own bounded budget. No truncation into a valid proposal; fail closed on overflow or malformed input.

Targets must be nonempty relative logical paths. Reject absolute/drive/UNC paths, slash prefixes, backslashes, colon, NUL/control characters, empty/`.`/`..` components, trailing separators, tilde prefixes and percent-encoded path syntax (no later percent decoding). First scope excludes hidden components, `.git`, `.env*`, credentials, build/cache directories and reserved runtime/config metadata. Require NFC path bytes and reject conservative case/Unicode-equivalent collisions and ambiguous names. Actual registered-volume equivalence and alias observations remain the future trusted context/broker responsibility; no volume rules are observed here. Content is never executed or interpolated. Reject duplicate/prefix-conflicting targets and path aliases; pure string validation is not OS confinement.

## Snapshot, authorization and validation order

1. Bound bytes/depth and strictly parse version/shape. Reject unknown kinds; validate IDs/digests and per-field/count/aggregate limits.
2. Bind the WF-owned response envelope to the admitted task, generation, provider request, context and deadline. A copied proposal ID does not create this binding.
3. Compare project identity/base digest against an injected trusted snapshot. Sort normalized UTF-8 relative paths bytewise; snapshot digest is SHA256 over the versioned, length-prefixed `(projectID, entry count, each path, revision tag/digest)` sequence. Integer lengths are unsigned64 big-endian. No locale, unordered JSON, timestamps, absolute paths or grant material in the digest. Digest comparisons require version equality.
4. Validate every create/update against file-specific expected revision, scoped editable-target allowlist and immutable policy revision. No model can broaden the supplied allowlist. A read-context grant is not a write grant. Reject nonregular files, symlinks/hardlinks/aliases and uncertain identity; actual handle/type/race checks belong to trusted adapters in 1B.2C/1B.4, not the pure 1B.2B validator.
5. Compute expected post-snapshot and a proposal digest over the versioned length-prefixed identity/base/ordered operation/path/revision/content bytes. Sort operations by canonical target; reject duplicates before hashing. Produce validated data or bounded rejection reasons. Validation success grants zero authority.
6. Trusted policy derives ApprovalRequirement. MainActor UI shows exact project, normalized diff, before/after hashes, limits and verification scope. Denial, expiry (at most300,000ms), revocation, changed digest/project/policy/revision or cancellation blocks dispatch. User approval cannot override invalid paths or stale revisions.
7. Only a separately implemented effect broker atomically consumes an unforgeable one-use dispatch capability bound to task/operation/session/generation, exact descriptor/project/base revision/policy/deadline. No public initializer or model-decoded field creates it. Revalidate handles/no-follow file identity, current hashes and generation after every await and immediately before effects.
8. Durable intent precedes effect; receipts and independent observations establish actual post-state. Partial/uncertain effects stop the chain and preserve unresolved intent. Never auto-replay/rollback on crash. VerifiedChangeResult is separate from the model claim; never mark build/test success without actual contained command evidence.

Snapshot entries cover all files admitted to the scoped transaction and collision checks; they are not a claim that an entire changing repository was atomically snapshotted. Revalidate the registered root and every affected file at use. Host changes outside the authorized snapshot do not silently become input/authority.

## Phase1B.2B implementation details and conservative limits

Domain/CodingProposal.swift contains all ten requested contracts. CodingProposal, both identifiers, ProposedFileChange and ExpectedFileRevision are Codable. Other report/observation/review values are Sendable data with explicit v1 schema, deliberately not the model wire schema. ApprovalRequirement groups proposal/project/base/post/policy/operation summaries in its `evaluation: ProposalValidationResult.Validated`; the remaining correlation/deadline/TTL fields are explicit. It is NOT a grant. VerifiedChangeResult and its receipts are report data, not proof; no production issuer/verifier or persistence encoding is introduced. Additional precise rejection codes are invalidEncoding, duplicateKey, invalidIdentifier, invalidHash, invalidSnapshot and fileAlreadyExists. Rejection returns one deterministic first reason without echoing raw input, within the ≤32 diagnostic ceiling.

`CodingProposalCodec.decode([UInt8])` is the sole supported hostile-byte boundary. Generic JSONDecoder/Codable cannot detect duplicate raw keys and must not be used directly on model bytes. The preflight scanner rejects every duplicate decoded key (including escaped equivalents), malformed UTF-8/unpaired surrogate escapes, noninteger numeric spellings, trailing documents, Markdown wrappers and BOM. Only version1 and exact variant keys then decode. Safe serialization is sorted-key JSON; encode/decode preserve exact content bytes, not dangerous path repair. Producer-side typed values are revalidated, including the actual serialized envelope size.

ProposalLimits fixes1MiB raw/encoded input,256KiB UTF-8 content/change,20 operations,1,024 path bytes/32 components,16 recursive value levels (root value counts as1),512 syntax nodes,32 keys/object,128 decoded key bytes and100 snapshot entries/editable targets. Twenty valid changes fit comfortably within the syntax budget; limits also bound malicious ignored-shape allocation. Scanner arrays cap at20 before typed decode. Swift/Foundation object/temporary overhead is not an OS RSS cap. Encoding may transiently allocate escaped JSON before rejecting the1MiB encoded limit; input content is already bounded (maximum escaped expansion approximately6×). Future streaming/transport must enforce its own allocation/buffer limits before this API.

The first scope rejects non-NFC path bytes rather than silently normalizing. Conservative POSIX-locale case folding rejects collisions/prefix conflicts even on a case-sensitive volume. These checks are intentionally stricter than some legal filesystem names and are not a claim to implement all actual volume normalization rules. No filesystem state is consulted. Snapshot fileState must agree with revision: regular+sha256 or absent+absent. Symlink/hardlink/directory/unknown states reject; no alias authenticity is inferred. NUL-containing content rejects as outside the initial regular-text scope.

Creates require an explicit absent entry; a missing snapshot entry is unknown and rejects. ProposalValidationContext supplies WF-owned expected proposal/project identity, snapshot/digest, editable target set, policy revision, expected/current generation, explicit clock/deadline and cancellation flag. A substituted proposal ID or mismatched/negative generation rejects as conflict. Context is injectable data, not a capability or live observation. Future adapters must bind it to the real admitted request/provider envelope and revalidate after suspension; this pure engine cannot attest caller provenance or observe time changing during a call.

Hash vectors use SHA256 and length-prefixed UTF-8 with unsigned64 big-endian lengths/counts/version. Snapshot stream: version, projectID, entry count, then byte-sorted (relativePath, revision) entries. Revision stream is length-prefixed `absent` or `sha256` followed by digest string. Only structurally consistent regular/absent entries hash, so fileState is inferred from the revision tag; unsafe states are not hashed. Proposal stream: version, proposalID, projectID, baseSnapshotDigest, change count, then byte-sorted (kind,path,revision,content) changes. Operation stream: version followed by that same change tuple. Content digest hashes exact UTF-8 without normalization. Returned operation/content hash arrays use the same canonical path order. No JSON order, process hash seed, locale sorting or wall timestamp enters digest bytes.

Structural success includes computed proposal/per-operation/content/post-snapshot digests. It does not create ApprovalRequest, OperationToken, dispatch authority, actual VerifiedChangeResult evidence, filesystem authorization or a safety/correctness judgment on generated code. Current Phase1A policy remains unchanged and rejects productive operations even after structural acceptance.

Exact-byte identity: ProposedFileChange equality compares relative-path/content UTF-8 bytes, so canonically equivalent Swift strings with different source bytes are not equal proposals. Policy revision labels are bounded nonempty ASCII tokens (`A-Z a-z 0-9 - _ : .`, at most128 bytes) and must match byte-for-byte. These restrictions prevent Unicode-equivalent metadata from hiding a changed revision; they do not confer authority.
