# Milestone 42A — Native window actions and clipboard-free dictation

30 October 2026, Asia/Calcutta. Build 42.0.1. Implementation and automated verification complete for the bounded capabilities below. Physical native window effects, quit timing, speech and clipboard-free input quality remain pending; no physical success is inferred from fixtures.

## Close verification

The user's saved close records showed needsReview / native-failure-or-unverified with no receipt. That establishes uncertain execution, not its exact native error. The old close implementation threw immediately when terminate returned false and otherwise checked only cached application instances for five seconds. It now sends normal termination requests, observes for up to ten seconds, and requires both original targets and fresh same-bundle running applications to be gone. Native termination state or ESRCH from a non-signalling kill(pid,0) check establishes absence when object notification lags. A live or relaunched same-bundle app prevents verified completion. Save/download dialogs remain under the app's control; no force quit, dialog dismissal or automatic replay is added. The change addresses stale/slow observation and the termination-request race; it is not a claim that every prior needsReview was false or every app must quit.

## New closed window capabilities

Agent voice/text requests such as Minimise WhatsApp / Minimize WhatsApp, Restore WhatsApp / Bring back WhatsApp, Make WhatsApp full screen / Full screen WhatsApp, Exit full screen WhatsApp, and Maximise WhatsApp / Maximize WhatsApp / Enlarge WhatsApp resolve an installed application identity and produce one typed window action. Identical repeated full window requests are folded once. Payloads in note/message replies stay literal. These deterministic requests do not require model availability.

NativePersonalWindows uses public Accessibility APIs, never generated scripts, arbitrary attributes, shell or keyboard shortcuts. It requires Accessibility trust, an installed identity, one running app instance, and a focused/main window or a single unambiguous window. The window owner must match the app process. Missing/ambiguous windows or unsupported AX capabilities fail transparently. It changes and reads back minimized/full-screen state, or positions/sizes the window to its display's visible frame for maximise (2-point tolerance). Multiple displays use the window's current center, Cocoa-to-AX coordinate conversion and visible frame. Restore unminimizes/activates; it does not promise to recreate an app window that has been closed. Full-screen transitions, app size constraints and unsupported attributes can still need review. Maximise means the available display frame, not arbitrary resizing or half-screen tiling. This adds these controls, not unrestricted system automation, content reading, file manipulation or communications.

New tool enum cases: minimizeApp, restoreApp, fullScreenApp, exitFullScreenApp, maximizeApp. Journal structure stays unchanged; old task records decode in the new build. An older build cannot decode records with these new cases and must not wipe the queue. Existing explicit Messages approval, durable write-ahead execution, receipts, cancellation and conservative restart recovery remain.

## Clipboard-free native dictation

Native insertion targets now advertise ClipboardFreeInsertionTarget. Safe verified AX direct edits retain their existing path; otherwise native dictation uses the existing bounded Unicode text-event delivery path, posted to the original process with target identity/focus/security checks. Supported text is nonempty single-line text up to 4 KiB UTF-8, with controls, line separators, paragraph separators, Return and tabs rejected. No clipboard snapshot/publication/restoration is performed on this route, and no backup is created. This includes identity-bound editors lacking complete readback, where the result stays dispatchedUnverified. Available exact readback can establish insertedVerified. Events are sent once, never retried, and partial/unverified delivery remains uncertain rather than completed. No conversation is submitted or send key generated.

Unsupported multiline/oversized text is retained for manual copy instead of automatically using a clipboard paste. A failed typed dispatch does not fall through to clipboard paste. Existing focus, secure-input, process/window identity, Terminal exclusions, selected-range checks and bounded delivery remain; no unsupported field is guessed. Normal waveform/Transcribing states and the requested hidden completion HUD remain. This is a material delivery-route change and requires physical comparison on actual editors, including Unicode and 5/20/45-second recordings. No live typing was injected by verification.

An already pending clipboard backup in the OLD running process still requires its existing ownership-bound confirmation or a superseding external clipboard change before normal quit. It is not discarded or silently persisted. New supported native dictation does not create such backups. Legacy injected/test adapters that do not opt into the new protocol retain the old guarded paste route; explicit user Copy commands remain clipboard operations. Clipboard-free delivery does not prove an unreadable editor consumed the events and cannot guarantee every application accepts Unicode events.
