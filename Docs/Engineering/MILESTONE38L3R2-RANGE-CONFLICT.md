Confirmed source defects, covered by deterministic regressions, are separate from the unknown physical rejection:

1. Modern attributed speech text was flattened before merging. `TranscriptBuffer.replace` rejected an overlapping volatile revision whenever an earlier pending range began before the new range. Word-timing data needed to preserve unaffected text was unavailable to the accumulator. A valid revision could therefore fail in application validation.
2. `resultsFinalizationTime` was ignored. Apple may finalize previously volatile, unchanged text without sending another final result for it. A subsequent result could encounter stale provisional content or fail the old out-of-order-final assumption.
3. Legacy full-utterance hypotheses used the same partial-range guard; a shifted speech start could be mistaken for a forbidden audio edit. Same-anchor shortening revisions could remain marked as unresolved resets.
4. A legacy epsilon could turn a genuinely overlapping metadata boundary into a permitted append. The remaining one-second/epsilon comparisons were removed; no replacement timing delay or arbitrary tolerance was introduced.

These are confirmed implementation defects; **linking any one of them to the reported 20-second operation still requires its actual metadata or a new physical failure trace**.

## Audio timeline and ownership audit

- AVAudioEngine ingress counts actual PCM buffers/frames and compares AVAudioTime sample positions at the source sample rate. The existing converter/tap, bounded queue, converter padding trim and EOF drain remain unchanged from R1.
- SpeechAnalyzer receives an ordered AnalyzerInput sequence in its input audio timebase. Modern `CMTimeRange` values remain rational CMTimes during reconciliation. Numeric values, positive timescales, epoch zero and nonnegative valid starts/durations/ends are checked before comparison. Invalid/indefinite/nonmatching epochs fail visibly. No wall-clock time is used as an audio offset.
- Modern attributed character indices are obtained only from Apple's time-range attribute helper. They are never treated as sample positions or compared to seconds.
- Legacy SFTranscriptionSegment timestamps/durations are request audio seconds; formattedString is an utterance hypothesis. Segment character ranges are not used as audio offsets. Public metadata anchors remain the only authority for the existing within-request passage retirement; timing regression alone never proves a new passage.
- Each recording owns a UUID session, a provider-task ownership token and a monotonically increasing task generation. Result closures check the recording's UUID before touching the accumulator. There is one provider task per recording; there is no automatic restart/rollover. New recordings start with fresh accumulators, so their zero-based task timelines are not mixed.
- Legacy callbacks retain the existing bounded FIFO and sequence guard. Modern results retain AsyncSequence order. Cancellation invalidates session ownership before cleanup; late old callbacks cannot mutate or insert into a new session. The existing repeated-session/cancellation/target tests remain in the full suite.

## Corrected reconciliation policy

Modern module construction now requests audioTimeRange attributes through `.timeIndexedProgressiveTranscription` (SpeechTranscriber) and `.audioTimeRange` (DictationTranscriber). Inspection, explicit installation, preparation and capture still use the same module factory. Added timing attributes do not authorize downloads or bypass installed-resource/preparation checks.

The accumulator keeps immutable committed text and bounded provisional pieces. A full-range revision supersedes its provisional hypothesis. A narrower overlapping revision uses per-word audio attributes to preserve the unaffected prefix/suffix and replace only intersecting text. A revision that falls in a verified silence gap inserts between the timed words. Empty modern text revokes only its provisional audio range. No lexical/fuzzy deduplication is used; repeated genuine words and Telugu/English are retained.

Finalization advances using the provider's `resultsFinalizationTime`, committing unchanged earlier provisional text as required. A boundary inside a provisional phrase can split at a verified word boundary. A boundary inside an indivisible timed word, or an overlapping range lacking a safe text/time mapping, still fails with retained prior text. Identical finalized callbacks do not duplicate output. A contradictory replay of a recent finalized range or a result crossing an immutable finalized prefix is rejected transactionally. Stale provisional callbacks wholly behind the final boundary cannot overwrite final text. Recent finalized replay records are bounded to 32; older stale ranges have no overwrite/append authority.

After hotkey release, existing capture shutdown/EOF drain and `finalizeAndFinishThroughEndOfInput` run first. The results task is drained before remaining unchanged provisional text is committed under that completed-analyzer guarantee. Only then can the existing insertion pipeline run. An interruption/failure never promotes a partial snapshot into successful automatic insertion.

Legacy formattedString revisions use a whole-utterance hypothesis scope within their current passage, allowing changed first-word timing without appending every partial. A public same-anchor hypothesis revision may shorten and resolve a provisional reset. Distinct verified non-overlapping metadata anchors preserve preceding passages. Unresolved resets remain bounded manual recovery and fail explicitly at finalization; no wall-clock offsets or invented task rollover are used. Legacy still has approximately one-minute provider restrictions and is labeled compatibility mode.

Safety bounds remain 64 KiB accepted text, separately bounded recovery, 256 provisional pieces, 32 recent final replay records, 32 native callback queue entries, eight unresolved legacy fragments, eight recent operation records and sixteen result-range observations per operation. Overflow remains explicit; no silent text truncation or transcript hashing is introduced.
